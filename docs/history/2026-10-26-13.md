## 2026-10-26 Hive Metastore 候选验证

已实现可复用的 `hms-register` / `hms-consume` 入口：11 组既有正式 Parquet 通过远端 Hive 表名读取，结果经独立 ODS 基准逐行核对后真实装载到隔离 READY generation。不是仅建表或查询诊断样本；当时作为候选验证，未切换活动指针；现已进入上节的默认链路迁移。

实际组合为 Spark 4.2.0/JDK 21、Hive 客户端/服务端 4.1.0、服务端 JDK 17.0.12、PostgreSQL 16.15，均为原生 arm64。339 个客户端 JAR 已离线打入镜像并记录来源与摘要。Hive `schematool -validate` 的版本、序列、表、位置及 NULL 检查均通过。

真实故障矩阵通过：部分登记阻断与恢复、缺表、位置错误、外部表删除保留文件、缺文件预检及 Spark 阻断、Metastore 停机拒绝消费、重建后表身份与消费恢复。故障仅作用于独立身份或复制产物。期间旧 API 282 次查询零错误，36 次资源采样无错误；采样内存最高 HMS 约 309 MiB、Spark 约 799 MiB，不能等同于绝对峰值。项目包含候选镜像和试验产物的保守占用约 12.1 GiB，低于 24 GiB 门限。

证据（相对于产物根）：`reports/metastore-0b3bea0fe74d4adc965f1f7f344d57c1/`；Schema 检查 `reports/metastore-schema-validation.log`；独立命令登记结果 `reports/hms-register-final.json`。前几轮因 provider 大小写、nullable 元数据语义及重复读取代码问题失败，均保留独立失败报告；修复后重新实际验证，不以部分成功抵消失败。
