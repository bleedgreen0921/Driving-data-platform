## 本轮推进顺序

1. 基线盘点与隔离：专用 Python、仓库外输入与产物、端口、其他容器基线。
2. 统一输入模型：单一 `nuscenes-mini-v2` 契约，`AssetPolicy` 只影响资产状态，不再维护两套执行路径。
3. PostgreSQL 源表镜像：独立 ODS schema、事务装载、逐字段核对、失败恢复、READY 写保护。
4. 结构化部署：原生 arm64 依赖，Spark/Parquet 独立对账、HMS 登记与按表名消费、服务 generation 发布。
5. API 与页面：媒体能力提示、generation 绑定筛选/详情/导出、实际浏览器查询。
6. 最终验收：五客户端、两轮加工、重跑、发布竞争与回滚、两库独立恢复及至少 1800 秒同时在线观察。

默认结构化版本为 `warehouse-v6`，ODS 版本为 `nuscenes-ods-v2`。`strict` 与 `registered` 使用同一处理版本；快照身份由表摘要与实际资产状态决定。历史向量版本与空间保持不变；本轮不部署模型、向量化或图文检索。

最新结果见[当前状态](current-status.md)，剩余修改见[修改清单](../CHANGE_REQUESTS.md)。
