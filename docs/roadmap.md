## 本轮推进顺序

1. 基线盘点与版本管理：保留工作区原有修改、修正忽略规则、隔离保存报告。
2. 配置与可移植性：统一路径、解释器、服务端口、备份位置及写入前安全校验；本地链路真实回归通过再放行。
3. 多模态图文检索后端：保留本地 llama，增加外部协议、独立 v3 空间、评测、构建与检索；协议测试和真实服务验收分开。
4. 入口收缩与内部整理：统一试验/诊断，退出旧JSON重新发布与无schema报告解析，保留数据只读及备份恢复。
5. 文档与历史：当前文档只描述现状及操作，按日期归档原验收，保留失败证据。
6. 最终验收：资源门禁通过后，完成真实故障、浏览器及至少1800秒全组件组合，含五业务客户端、文本/图片探针、两轮加工、重跑回滚与两库独立恢复。

默认结构化处理版本为warehouse-v5，向量加工版本为embedding-real-v3；冻结历史产物与旧空间不改写。新代码须按身份约束重新评测或加工，不放宽校验复用旧产物。

当前机器尚无项目运行配置，外部服务尚未选定；真实验收条件不足时记录阻断，不用原机器或协议测试结果代替。最新结果见[当前状态](current-status.md)，剩余修改见[修改清单](../CHANGE_REQUESTS.md)，历史阶段见[归档索引](history/README.md)。
